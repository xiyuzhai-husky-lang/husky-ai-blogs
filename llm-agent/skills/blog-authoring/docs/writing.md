# Writing

The user wants concise information, a powerful argument, and fluent language.
Save reading time by choosing what matters and making it easy to follow.

## Develop the argument

State the main claim and its significance in the opening paragraph. Let each
subsequent section answer a question raised by the preceding argument. Use
concrete examples and evidence where they advance the point.

Cut repeated conclusions, generic introductions, unnecessary background, and
detail that changes no conclusion. Keep the causal links that let the reader
understand how one statement follows from another. Section count and length
should follow the subject, not a template quota.

## Preserve flow

Vary sentence length naturally. Split a sentence when nested clauses make it
hard to follow, not merely because it is long. Connect closely related ideas
when separate short sentences would sound mechanical.

Over-compressed:

> A pull request can contain all of this. My workflow makes it required. The
> code is one part. The evidence is another.

Fluent and direct:

> A pull request can contain all of this, but my workflow makes the fuller
> account a requirement. The code becomes one part of the deliverable,
> alongside the evidence needed to judge it.

Do not use word-count reductions as the quality target. Avoid turning paragraphs
into slogans, stacking bold conclusions, or forcing every sentence to stand
alone. A strong argument comes from the reasoning, not emphatic formatting.

## Evidence and scope

Separate established results, implementation proposals, and predictions. Cite
primary sources near the claims they support, and preserve units, samples, and
assumptions behind quantitative comparisons. A limitation belongs where it
changes how a claim should be understood; do not repeat it throughout the essay.

Use the author's perspective when it contributes an observation or argument.
Do not automatically add a personal learning disclaimer, novelty disclaimer,
or statement of mission. The user removed that opening note from the first
essay. Include such framing only when requested for the particular article.

Finish with a reading pass: does every paragraph advance the argument, and can
a reader follow it without mentally reconnecting fragmented statements?
